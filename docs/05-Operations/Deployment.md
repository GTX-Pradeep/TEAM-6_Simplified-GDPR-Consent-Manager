# Deployment (issue #18)

The whole system runs as **one free Render web service**: the Express API serves the built React app,
so pages and API share one address (for example `https://gdpr-consent-manager.onrender.com`).
The database is **Neon PostgreSQL**. Covers **NFR-4** (availability) and **SEC-5** (HTTPS).

```
Browser --HTTPS--> Render web service (Node 20)
                     |-- /            React app (client/dist)
                     |-- /api/v1/...  Express REST API
                     '--TLS--> Neon PostgreSQL
```

## 1. Production database (Neon), 5 minutes

Use a **separate database** for production, so test data from development never mixes in.

1. Neon console -> your project -> **Databases** -> **New database** -> name `gdpr_prod` -> Create.
2. **Connect** -> choose database `gdpr_prod` -> turn **Connection pooling OFF** -> copy the string
   (`postgresql://...neon.tech/gdpr_prod?sslmode=require`). Do not share it.

## 2. Deploy on Render, 10 minutes

1. Go to **render.com** -> **Get started** -> sign up **with GitHub**.
2. **New +** -> **Blueprint** -> connect the repository `TEAM-6_Simplified-GDPR-Consent-Manager`.
3. Render reads `render.yaml` and asks for **DATABASE_URL** -> paste the Neon string -> **Apply**.
4. Wait for the first build (about 5 minutes). The log ends with `Seed done ...` and then
   `API listening ...`. Render shows the address at the top: `https://gdpr-consent-manager.onrender.com`.
5. Open it and log in with a demo account (`user@demo.com` / `Demo@12345`, `admin@demo.com`, `dpo@demo.com`).

What the build does: installs packages, builds client and server, applies the database migrations
(tables, triggers) and creates the demo data if missing. Every merge to `main` deploys again automatically.

Secrets: `JWT_SECRET` and `EMAIL_ENCRYPTION_KEY` are generated by Render once and kept. **Never change
`EMAIL_ENCRYPTION_KEY` later**: stored e-mail addresses could no longer be read.

## 3. Keep it awake and measure availability (NFR-4), 5 minutes

A free Render service sleeps after 15 minutes without visits (the first visit then takes about 50 s).

1. **uptimerobot.com** -> free account -> **New monitor** -> type **HTTP(s)**.
2. URL: `https://<your-app>.onrender.com/api/v1/health`, interval **5 minutes** -> Create.

The monitor keeps the service awake and its dashboard shows the uptime % for the evaluation period.

## 4. Check after deployment

| Check | Expected |
|---|---|
| `https://<app>/api/v1/health` | `{"status":"ok","db":"up",...}` |
| `http://<app>/` (plain http) | redirected to `https://` (SEC-5) |
| log in as `user@demo.com`, Grant / Withdraw | works, badge "API & database online" |
| refresh the browser on `/dashboard` | page loads (no 404) |
| Neon -> `gdpr_prod` -> table `users`, column `email` | shows `enc:v1:...`, not addresses (NFR-10) |
| DPO console -> **Verify integrity** | "All records intact" |
